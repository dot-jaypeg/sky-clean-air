# Sky Clean Air — Project Notes

Site build for Sky Clean Air (skycleanair.com), family-owned HVAC company founded 2018 by Nadav ("Nadi") Offer and Daniel Lezmy. Home base San Diego County; actively launching Orange County. The Inland Empire was removed from the site entirely at the client's request (2026-10-01) — don't mention it anywhere. See `references/onboarding-info/` for the client brief.

Design direction: moody dark-navy hero with a glowing cyan/teal gradient (`#2addea` / `#2dd2c7` / `#23d4d7`, pulled from the SCA logo mark), transitioning into clean light sections. Antonio for headlines, Inter for body copy.

## How the site is built

Multi-page static site generated by a small stdlib-only Python builder (Python 3.8 — no f-string quote nesting, no third-party packages).

- `python3 tools/build.py` → writes every page to `public/<path>/index.html`. `--check` also reports broken internal links.
- Preview: `python3 -m http.server 8791 -d public` (port 8765 is often taken by another project's server).
- `public/` is the deploy root. `public/css`, `public/js`, `public/assets` are hand-edited source; every `.html`, `sitemap.xml`, `robots.txt` in `public/` is **generated — never hand-edit it**, change the source and rebuild. `public/.generated.json` tracks generated files so stale pages get deleted.
- `src/data/*.json` — single sources of truth: `site.json` (phone, address, specials, widget embeds, mascot artwork, `show_placeholders`), `services.json` (every service page + category), `areas.json` (regions → cities, status, coordinates), `team.json`, `reviews.json`.
- `src/pages/**/*.html` — hand-written pages: front matter (`title`, `description`, `path`, `body_class`) + HTML, with `{{phone}}`/`{{tel}}`/`{{founded}}` variables and `{{component:name[:arg]}}` blocks from `tools/components.py`.
- `tools/sitelib.py` — shared chrome (head, header/mega-menu, mobile drawer, footer) and building blocks. `tools/generators.py` — the ordered list of page generators: `gen_services.py` (the 8 service pages, /services/, redirects from old service URLs), `gen_areas.py` (/service-areas/ map hub, region + city pages), `gen_team.py` (/our-team/ by department), `gen_legacy.py` (blog, misc legacy pages, retired-URL redirects).
- **Services = 8 pages, one per category**, at `/services/<category>/` (client decision 2026-09-29). Copy: `src/content/services/_<category>.html` — front matter `title/description/h1/lede` + HTML body; a final `<h2>Frequently Asked Questions</h2>` of `<h3>`/`<p>` pairs becomes the FAQ accordion + schema. The sub-services in `services.json` (with one-line `summary`s; commercial ones have a `group`) are listed in each page's "What's included" section — they are NOT separate pages. The nav's Services dropdown lists just the 8.
- Retired URLs: every old individual-service URL (`/ac-repair/`) redirects to its category page; the 1,613 legacy service × neighborhood pages (`/air-duct-cleaning/clairemont/`) redirect to that neighborhood's `/service-areas/<slug>/` page (hub if none). Use `site.redirect(old, new)` in a generator — the builder writes a canonical + meta-refresh stub (static host, no real 301s) and rewrites every internal link straight to the final URL.
- City intros for non-legacy cities: `src/data/area-copy.json`.
- Hand-built pages in `src/pages/`: home, about (`/about-us/`), contact (`/contact-us/`), specials, testimonials, careers, about/gallery. All forms are front-end prototypes (`data-quote-form`) — not wired to a CRM yet (client uses Workiz, moving to Menaia).
- Legacy migration (the old site is WordPress/Elementor, ~1,900 pages + 1,225 posts): `tools/scrape_legacy.py` (metadata → `content/legacy/meta/`, raw HTML cached gzipped in `~/Library/Caches/sky-clean-air/legacy-raw/`, outside iCloud) → `tools/parse_legacy.py` (clean content → `content/legacy/{pages,posts}/<id>.json`, committed) → `tools/fetch_legacy_images.py` (client-owned images → WebP in `public/assets/legacy/`, map in `content/legacy/image-map.json`). `tools/gen_legacy.py` renders service × neighborhood pages, blog posts + `/blog/` index, and misc pages; `tools/gen_services.py` renders service pages, category hubs and `/services/`. Be gentle with their live server — its REST API takes ~7s per content request; the front-end HTML is page-cached and fast.
  - `RETIRED` in `gen_legacy.py` lists legacy URLs replaced by new pages, drafts (`-delete` duplicates, `homepage-hero-concept`, `*-old`, `*-nw`) and ones that now meta-refresh elsewhere. Paid-ads LPs/thank-you pages (`NOINDEX`) are migrated but noindexed.
  - ~18 legacy images were hotlinked from other companies' websites — deliberately not migrated.
  - Legacy copy hard-codes (858) 346-5551; the parser turns every phone number into `{{phone}}` so the site uses `site.json`'s number everywhere.
- URLs deliberately match the legacy WordPress URLs (trailing slash, same slugs) so SEO carries over.

### Scalable service areas
Adding a market = edit `src/data/areas.json`: add a region (`status`: `active` / `launching` / `coming-soon`) and its cities, run `python3 tools/geocode_areas.py` to fill coordinates, rebuild. Coming-soon regions show on the map/lists but get no city pages until their status flips. A city can override its region's status with its own `status`.

### Pending assets (placeholders)
`site.json → show_placeholders: true` shows labeled dashed boxes where pending assets go: Contractor Commerce widget (contact page), reviews-aggregator widget (homepage, reviews page, service/region pages — falls back to `reviews.json` testimonials), the empty HVAC Installation Team department and team members with `role_pending`. Paste widget embed code / artwork paths into `site.json` and rebuild. Set `show_placeholders` to `false` before launch. The legacy site already runs Trustindex (4.9★, 833 reviews) — likely the client's existing reviews account.

### Skyler the mascot — use SPARINGLY and deliberately
Client direction: Skyler (the Home Service Eagle; source art in `assets/mascot/`, web copies in `public/assets/mascot/`) is **never on the homepage** and must feel designed-in, not dropped in. Current placements: the About page "Meet Skyler" brand panel (he stands on the panel and breaks out of its top edge), and the closing CTA band on Contact, Specials and the /service-areas/ hub, where he stands at the end of the band with a page-specific speech bubble (`{{component:cta:Bubble text}}`). Don't add him elsewhere without being asked.

### Icons
Service and UI icons are Lucide (ISC license) and social icons are Simple Icons (CC0), embedded as SVG in `ICONS` / `SOCIAL_ICONS` in `tools/sitelib.py`. Use `icon('name')` in Python or `{{icon:name[:size]}}` in page sources. Don't hand-draw icons. To add one, copy its SVG body from lucide.dev into `ICONS`.

### Favicon
`public/favicon.ico` + `public/assets/logos/favicon-{32,192}.png` / `apple-touch-icon.png` are the ORIGINAL logo file centered on a square canvas — never stretched or cropped (client: keep the logo in its original format).

## Git workflow — standing authorization

The user has authorized automatic git management for this repo. Unless told otherwise for a specific change:

- After making a meaningful set of file changes, stage, commit, and push to `origin main` without asking for confirmation each time.
- Still follow standard git hygiene: review `git status`/`git diff` before staging, write a clear commit message describing the "why," never force-push, never skip hooks, never amend existing commits (always create new ones).
- Still pause and ask before anything destructive or hard-to-reverse (history rewrites, branch deletion, resetting shared history) — auto-push of normal forward commits is in scope; those are not.
- If a commit touches something that looks like it could contain secrets/credentials, stop and flag it instead of pushing.
- Commit only the files relevant to the task just completed — don't sweep up unrelated untracked/modified files sitting in the working tree.
